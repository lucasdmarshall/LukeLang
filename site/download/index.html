Build it from source.

LukeLang has no installer yet, and that is deliberate — the compiler is a single C++ binary you can build in under a minute, and building it is how you know it works on your machine.

Quick install

git clone https://github.com/lucasdmarshall/LukeLang.git
cd LukeLang/vm && make
./build/luke BUILD ../examples/build/hello.luke -o hello && ./hello

The compiler lands at vm/build/luke. Put it on your PATH if you want to call it from anywhere: 

export PATH="$PWD/build:$PATH"

Requirements

  • C++17 compiler

    g++ or clang++. This builds the compiler itself.

  • A C compiler

    cc / gcc / clang. Build mode emits C and then invokes this to produce the binary.

  • make

    Drives the compiler build and the test suite.

  • git

    To clone, and for the version stamp in build output.

That is the whole core. Everything below is only needed for the feature you are actually using — WebAssembly targets, SQLite, Postgres, or authentication.

Platforms

Linux

# Debian / Ubuntu
sudo apt install build-essential git

# Fedora
sudo dnf install gcc gcc-c++ make git

macOS

xcode-select --install

Apple's command line tools provide clang, clang++ and make. Both Apple silicon and Intel work.

Windows

Build under WSL2 with a Linux distribution and follow the Linux instructions. The native Windows toolchain is not a supported target yet.

Optional dependencies

Each one unlocks a specific part of the standard library. The compiler builds and the core language runs without any of them.

  • WASI SDK

    Needed for -target wasm and -target browser. Unpack it at .tools/wasi-sdk in the repository, or point LUKE_WASI_SDK at wherever you installed it.

  • SQLite

    libsqlite3-dev — for import std/sqlite, and for every Live Graph example.

  • libsodium

    libsodium-dev — Argon2id password hashing behind import std/auth.

  • libpq

    libpq-dev plus a running Postgres — for import std/pg and the Slipstream executor.

  • gdb

    Only for the debugger checks in the test suite (DEBUG --break and --inspect).

  • Node.js

    Runs the browser-target examples headlessly through the bundled loader script.

# everything, on Debian / Ubuntu
sudo apt install build-essential git libsqlite3-dev libsodium-dev \
  libpq-dev postgresql gdb nodejs

Verify the install

The test suite is the acceptance gate for the whole project. If it passes on your machine, your install is good. 

cd LukeLang/vm
make test               # Play VM + Build mode
make test-syntax-v2     # syntax v2 gates
make test-lsp           # language server providers

Targets that need the WASI SDK are skipped when it is absent, and the Postgres examples are skipped when no server is reachable — so a core-only install still gets a green run.

Editor tooling

The official extension is on the Visual Studio Marketplace. Install it from the Extensions panel by searching lukelang, or from a terminal: 

code --install-extension lukelang.lukelang-vscode
Get it on the Marketplace Extension source

  • VS Code extension

    Syntax highlighting, snippets and brace-aware indentation for .luke and .lk, plus the language server and debugger below.

  • Language server

    luke LSP speaks LSP over stdio — hover, completion, definition, document symbols, formatting and diagnostics.

  • Debug adapter

    luke DAP for editor debugging; luke DEBUG --break file:line drives gdb directly, with breakpoints on your source lines.

  • Formatter

    luke FMT file.luke — round-trip safe, and checked as such in CI.

Setup details are in editor tooling.

Packages

LukeLang ships a small package manager. Dependencies resolve into luke_modules/ and lock to a content hash in luke.lock. 

luke PKG init
luke PKG install greeter
luke PKG lock
luke PKG publish

Then import it like any other module:

import luke/greeter
